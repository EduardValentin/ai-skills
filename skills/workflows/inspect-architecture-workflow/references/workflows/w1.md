# W1. Dependency direction and ports

Reads: the assess output, query ring-crossings (outward and inward), ports, signatures <path> per port, entry-points, edges --kind constructs, volatility.

Procedure:
1. For every edge with `crosses-ring` yes, compare the rings at both ends.
2. For every port `query ports` lists, note the owner's ring; the signature's types come from `query signatures <path>`, or from a fact slice when it prints `not provided by the adapter`.
3. For every place a concrete detail is constructed, check whether the constructing unit is a composition root. The construction sites are the rows of `query edges --kind constructs`; when it lists none because the adapter does not provide `constructs` (`arch assess` then prints `construction rows not provided by the adapter`), `query entry-points` lists what each entry point imports and construction sites elsewhere come from a fact slice.
4. For every use case, check that its callers depend on an input boundary and that it reaches presenters and stores through boundaries it declares.
5. For every high-level unit in a component `query volatility` shows changing, classify each change's reason as policy or detail; a reason the packet lacks is an open question for a fact slice.

Rows marked "assessed by the command" come decided in the `arch assess` output, which the coordinator merges, whenever the mark's condition (mode, adapter fact) holds; otherwise they are yours: do not re-derive or return them, and judge only the other rows. In plan review, apply them to `proposed` rows yourself; the command cannot see those.

| Condition | Verdict | Rule | Base severity |
|---|---|---|---|
| Edge from a policy unit (entity, use-case, port, boundary-data) to a detail unit or `external:` framework, vendor, or runtime (assessed by the command) | SHOULD_CHANGE | R4 | blocker |
| Edge crosses rings outward for any other unit (assessed by the command) | SHOULD_CHANGE | R4 | blocker |
| Port owner is in a lower ring than its consumer, or the port sits in a shared interfaces bucket with no consumer beside it | SHOULD_CHANGE | R5 | blocker |
| Port signature names a detail type or an `external:` type | SHOULD_CHANGE | R5 | blocker |
| Direct edge remains between a policy unit and a detail unit that also share a port | SHOULD_CHANGE | R5 | blocker |
| Controller imports the use-case class rather than an input boundary; use case imports its presenter or gateway implementation | SHOULD_CHANGE | R6 | blocker |
| Concrete detail constructed in a unit that is not a composition root (assessed by the command when the adapter provides constructs) | SHOULD_CHANGE | R7 | blocker |
| High-level unit changed for a detail reason in two or more recent changes | SHOULD_CHANGE | R4 | blocker |
| Abstraction with exactly one consumer and one implementer and no named deferred decision or forbidden ripple | SHOULD_CHANGE | R8 | minor |
| Otherwise, for each cross-ring edge and port | OK | R4, R5 |  |

Writes: one row per cross-ring edge, port, construction site of a concrete detail, and use case;
a port's row carries its direction verdict.
